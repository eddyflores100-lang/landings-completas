# From demo to client delivery

1. Agree on the goal, audience, pages, CTA and acceptance criteria. Quote the implementation scope and any external services separately.
2. Copy or fork the source for the client. Replace the fictional brand, colors, template copy and contact address. Use owned/authorized images and verified facts only.
3. Define the real contact flow: approved inbox draft or a separately implemented server-backed form. Never display “sent” when no server confirms receipt.
4. Add actual business disclosures and privacy details for the real workflow. Remove demo labels/noindex only from the client-specific reviewed site, never from this public demo catalogue.
5. Build and verify all local links, keyboard navigation and narrow/large layouts. Test contact receipt with an authorized test; demo mailto links alone do not prove inbox delivery.
6. Confirm hosting/domain ownership and publish only the generated files. Test the live URL, support route and rollback, then hand over source and instructions.

## Scope by template

- Consulting / agency: actual services and authorized case studies; no fabricated performance claims.
- Education: actual program and enrollment conditions; certification/learning platform not supplied by a landing template.
- Wellness: activities and studio contact; no clinical features or health outcome promises.
- Real estate: reviewed property facts and media rights; no live inventory or MLS implied.
- SaaS / startup: distinguish working capabilities from a roadmap; no fake signup, billing or customer statistics.

## Catalogue status

All seven are editable demo structures. They are not seven businesses ready to collect payments. The collection supports selling a scoped website adaptation service. There are no prices or guaranteed schedules until a proposal is agreed.
